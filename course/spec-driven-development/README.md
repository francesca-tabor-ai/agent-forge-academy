# Mastering Spec-Driven Development (SDDD)

## 📚 Course Overview

**Duration:** 6 weeks (7 total with capstone)  
**Level:** Intermediate to Advanced  
**Time Commitment:** 6-8 hours per week  
**Prerequisites:** Software development experience (2+ years), basic AI/LLM knowledge

---

## 🎯 What You'll Master

By completing this course, you will be able to:

✅ Replace "vibe coding" with structured, traceable development  
✅ Shift from implementation-focused to intent-focused development  
✅ Capture requirements in high-level specifications  
✅ Use clarification loops to surface gaps before coding  
✅ Codify governing principles and standards  
✅ Break down complex projects into actionable tasks  
✅ Implement TDD workflows with AI agents  
✅ Navigate the SDDD tooling ecosystem  
✅ Understand enterprise economics and strategy  
✅ Implement governance and compliance frameworks

## 📋 Course Modules

### [Module 1: The End of "Vibe Coding"](Module_01_The_End_of_Vibe_Coding.md)
- **Lesson 1.1:** The Problem of Vibe Coding. Understanding why throwing vague prompts at AI leads to chaos, technical debt, and inconsistent code that fails in production.
- **Lesson 1.2:** The SDDD Philosophy. Shifting the "source of truth" from the code to the specification.
- **Lesson 1.3:** Intent over Implementation. Learning to focus on what to build and why, rather than the mechanical "how".
- **Lab 1:** Analyze a "vibe coding" project and identify technical debt

### [Module 2: From Ambiguity to Precision (Specify & Clarify)](Module_02_From_Ambiguity_to_Precision.md)
- **Lesson 2.1:** Phase 1: Specify. Capturing user stories and business requirements in high-level markdown files.
- **Lesson 2.2:** Phase 3: The Clarification Loop. Using AI to "formally quiz" the developer, surfacing gaps in logic, and resolving stakeholder misalignments before coding begins.
- **Lesson 2.3:** Governing Principles (The Constitution). Codifying non-negotiable standards (e.g., minimum 80% test coverage or specific tech stacks) that the AI must follow.
- **Lab 2:** Create a specification document with clarification loop

### [Module 3: Engineering the Blueprint (Plan & Taskify)](Module_03_Engineering_the_Blueprint.md)
- **Lesson 3.1:** Technical Planning. Translating requirements into architecture, data models, and API contracts.
- **Lesson 3.2:** Task Breakdown. Decomposing the plan into small, actionable, and testable tasks that AI agents can execute sequentially.
- **Lesson 3.3:** Context Engineering. Managing the "paper trail" to prevent "context collapse," where the AI forgets previous decisions.
- **Lab 3:** Create a technical plan and task breakdown for a project

### [Module 4: Agentic Implementation & Quality Assurance](Module_04_Agentic_Implementation_and_Quality_Assurance.md)
- **Lesson 4.1:** The Human Pilot. Transitioning the developer's role into a "decision manager" who validates AI output at explicit checkpoints.
- **Lesson 4.2:** Test-Driven Development (TDD). Ensuring AI agents write and pass unit tests for every task before it is considered "complete".
- **Lesson 4.3:** Automated Validation. Using tools like Playwright for live browser verification to ensure the final product matches the spec.
- **Lab 4:** Implement a feature using TDD with AI agents

### [Module 5: The SDDD Tooling Ecosystem](Module_05_The_SDDD_Tooling_Ecosystem.md)
- **Lesson 5.1:** AWS Kiro. The IDE for "production readiness," using a three-phase workflow (Requirements, Design, Tasks).
- **Lesson 5.2:** GitHub Spec Kit. The "structured architect" for new (greenfield) projects requiring strict enterprise governance.
- **Lesson 5.3:** OpenSpec. The "agile renovator" for maintaining and improving existing (brownfield) codebases with minimal overhead.
- **Lesson 5.4:** BMAD Method. Orchestrating a "Specialized AI Team" (Analyst, PM, Architect, Dev, QA) for massive enterprise-scale projects.
- **Lab 5:** Set up and use one SDDD tool for a project

### [Module 6: Enterprise Economics & Strategy](Module_06_Enterprise_Economics_and_Strategy.md)
- **Lesson 6.1:** The Headcount Shift. Moving from large dev teams to fewer, senior "High-Leverage Human Pilots".
- **Lesson 6.2:** Cost Realignment. Replacing "people-heavy coordination costs" with "software-heavy orchestration costs".
- **Lesson 6.3:** The Learning Curve. Navigating the 3–6 month productivity dip as teams unlearn "vibe coding" and adapt to formal specifications.
- **Lesson 6.4:** Governance & Compliance. Auto-generating audit trails from specifications for regulated industries (e.g., Telecommunications and Finance).
- **Lab 6:** Create an enterprise SDDD adoption plan
